# 空输出预算止损

上游返回 `max_tokens`，但没有有效正文和工具调用时，独立 CLI 的下一轮无法恢复被截断的思考。继续返回空正文和 `max_tokens` 会让本地 Claude Code 自动发送续接，重复消耗额度。

网关默认执行以下止损：

- 首次失败返回明确标注来源的网关提示，以 Anthropic `end_turn` / OpenAI `stop` 结束；保留该次真实上游用量。
- 相同失败请求在同一网关进程内拦截一小时，流式与非流式共用指纹；排队后再次检查，避免排队重发启动 CLI。最多保存 256 条失败指纹。
- 历史末尾出现已观察到的完整 `Output token limit hit…` 自动提示，且紧邻空助手、被转换省略的助手或网关止损提示时，直接终止，不认证、不启动推理。不匹配引用、普通“继续”、工具结果或已有有效正文的截断续接。
- 拦截响应为正常的终止消息，不返回可能触发 SDK 重试的 429/502 或 SSE error；不重复报告之前的用量，不伪造模型完成任务。

失败指纹为进程随机密钥的 HMAC，仅驻留内存，不记录正文、思考、工具参数或指纹日志。改变任务、模型、思考强度或输出预算后可重新请求；没有静默降低档位或增加预算。

边界：首次耗尽已发生的消耗不能撤销。本补丁不保存思考状态，也不消除上游本身的过度思考。进程重启、超过一小时或容量淘汰后，相同原始请求不再被指纹拦截；已知格式的空回复自动续接仍由历史结构检测拦截。尚未完成的并发相同请求不会合并。新增自动提示措辞、丢失历史或自动压缩后的循环需另行验证，不能宣称全部自动重试已被覆盖。

阶段日志记录 `empty_output_limit_stopped` / `empty_output_retry_blocked`，最终结果为 `empty_output_limit` / `blocked`；网关合成提示不冒充模型首段正文。
