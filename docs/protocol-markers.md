# 协议标记与隐写边界

记录日期：2026-10-11。适用基线：网关 0.11.18；本次查询的云端官方 Claude Code 为 2.1.296。

## 当前决定

维持现有协议字段校验与转换。Unicode 标记、正文中的日期与标点、模型输出中的文本水印继续保留，不增加清洗或改写。更全面的标记审计作为后续改进项，本次不修改运行行为。

这里的协议处理不等于清除所有指纹，也不保证上游无法识别中转架构。

## 已确认的处理

- `model-gateway/anthropic.mjs` 仅移除每个顶层系统文本块开头的 `x-anthropic-billing-header` 行，正文内引用不删除。这是避免前端旋转元数据干扰缓存的既有处理。
- 云端官方 CLI 负责认证和构造最终上游请求。网关不自行生成、伪造或修改其上游 billing 标记和认证身份。
- 调用方的 `metadata` 字段被接受，但当前转换器不会将其复制到云端上游请求；上游 CLI 自己生成的元数据仍可能存在。
- 合成检查确认：输入中的 Unicode 撇号和日期分隔符经过协议转换、上下文编译后保留；输出正文中的同类字符也原样转发。
- `RELAY_PROMPT` 明确说明云端 CLI 与调用方工具的执行边界。历史会按 JSON 文本块包装，工具经 MCP 映射，因此最终请求不与客户端原始请求逐字相同。
- 加密隧道保护传输过程，不阻止上游读取已经发送的提示词、历史、工具定义或工具结果。

## 外部报告与证据范围

[Thereallo 的原始逆向报告](https://thereallo.dev/blog/claude-code-prompt-steganography)分析 Claude Code 2.1.196：客户端可依据自定义 API 域名与时区，将分类结果编码在日期句子的 Unicode 撇号和日期分隔符中。这证明的是报告所分析版本的机制，不能直接证明当前 2.1.296 仍存在同一实现。

[Anthropic 的内容标记说明](https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content)介绍模型层文本水印及文件来源凭据。模型输出水印与客户端环境指纹是不同机制；公开说明不足以证明水印包含账户身份、请求报错或完整对话记录。

当前没有证据将此前 MCP 失败归因于隐写或风控。已确认的兼容缺陷是旧工具数量上限 128；0.11.18 调整为 512。修复后的自然请求中观察到每轮 188 个工具，最近八轮云端请求成功，桌面会话出现 Linear 工具调用及正常结果。该观察不替代完整协议审计，也不保证未来请求持续成功。

异常通道告警主要检查思考与正文通道的候选异常，不检测全部隐写或水印；没有告警不能解释为没有标记。

## 后续改进项

若后续需要更完整的验收，再对指定 CLI 版本进行隔离的回环模拟上游检查：

1. 比较客户端输入、网关编译结果与 CLI 最终请求，明确新增、移除和改写的字段。
2. 对日期句子等已知位置记录字符码点和差异，区分普通排版与具有证据支持的标记机制。
3. 在 CLI 升级验收中检查工具定义、图片、历史顺序和元数据的变化，避免把旧版逆向结果当作新版事实。
4. 使用合成内容，不持久化认证值、隐藏思考、工具参数或真实对话全文。

以上事项尚未实施，本次记录不承诺移除 Unicode 标记或模型水印。
