# 会话额度止损

官方 CLI 返回失败结果 `You've hit your session limit …` 时，旧网关将其包装成 502，客户端会当作临时服务故障反复重试。开新会话也无法恢复同一账户的额度。

0.11.12 对此明确错误返回 `[claude-code-relay:SESSION_LIMIT]` 合成提示，以 Anthropic `end_turn` / OpenAI `stop` 结束，JSON 和 SSE 均不返回可触发重试的 429/502 或 SSE error。提示标明网关来源，不表示模型完成了任务。首次保留 CLI 提供的真实用量，拦截响应不重复报告。

账户冷却在认证和启动 CLI 前检查，排队及认证结束后再次检查，覆盖换会话和换模型的请求。仅保存提示与期限，不保存请求、原始错误或对话正文。

重置时间只有在明确包含有效的 12 小时制时刻和 IANA 时区，且未来五小时内能确认时才采用；按上游时区计算，兼容午夜和夏令时。未识别或无法确认时间时只冷却一分钟，之后允许用户手动重试。到期只解除拦截，不自动发送请求，也不保证上游已经恢复。

边界：只识别 CLI 的失败结果中的明确会话额度错误，普通限流、网络错误、周额度错误及正常正文引用不会触发。已输出有效正文后仍保留原错误，后续请求受冷却保护。已经执行中的并发请求不会被中断。冷却只在当前进程内生效，重启后重新识别；没有修改模型、预算或思考档位，也不会启用额外付费额度。

阶段日志记录 `session_quota_stopped` / `session_quota_retry_blocked`，最终结果分别为 `session_limit` / `blocked`，合成提示不记作模型首段正文。
