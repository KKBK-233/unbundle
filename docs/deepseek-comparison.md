# DeepSeek 复测：链路、缓存与审计质量

日期：2026-09-30。被审计源码固定为 `bb6107cfd0350dcf3a71e5f812a35abd2b2a28f3`；新网关来自 `ddbbc80`。固定源码用于对照，不把模型针对旧代码的反馈当成新版缺陷。

## 条件

本地 OMP → frp STCP / 双向 TLS → 云端网关 → 官方 Claude Code 2.1.277 → DeepSeek Anthropic 兼容 API，模型 `deepseek-flash`。本地只开放读取工具，只提供已提交源码快照。模型未执行云端工具。

三组均使用相同审计提示：最多三次 read，分别读取 engine/context/server，给出简体中文审计报告。均关闭 DeepSeek thinking，上游输出上限 4096；每组一轮采样。没有把正文、凭据或 OAuth 写入指标记录。

## 结果

| 测试 | 上游成功请求 | 未缓存输入 | 缓存读取 | 总输入 | 输出 | 网关执行累计时间 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧网关 | 4 | 43,183 | 0 | 43,183 | 1,074 | 16.337 秒 |
| 新网关，保留 CLI metadata | 4 | 43,250 | 0 | 43,250 | 1,042 | 14.604 秒 |
| 新网关，固定 DeepSeek 测试用户 | 4 | 14,814 | 28,416 | 43,230 | 1,642 | 18.563 秒 |

总输入 = input_tokens + cache_read_input_tokens + cache_creation_input_tokens；三组缓存创建字段均为 0。时间为网关各请求的 durationMs 之和，不含 OMP 启动、隧道准备和清理。输出长度不同，耗时不可直接归因于缓存。没有从 token 推算账单金额。

第三组各轮缓存读取：0、6,784、10,368、11,264。总输入缓存命中率 65.73%；末轮 11,264 / 12,270 = 91.80%。未缓存输入相对旧网关减少 65.7%，总输入变化约 +0.11%。第二组总输入变化约 +0.16%。

## 为什么前两组没有缓存

记录显示第二组第 2～4 轮工具/系统提示哈希相同，首消息块哈希相同，但 metadata 哈希每轮不同。

[DeepSeek 文档](https://api-docs.deepseek.com/guides/anthropic_api/)说明：Anthropic 格式中的 metadata.user_id 生效，cache_control 被忽略。[隔离说明](https://api-docs.deepseek.com/quick_start/rate_limit/)明确 user_id 用于业务用户的 KVCache 隔离。

第三组在**仅供 DeepSeek 的临时适配器**里，每次实验随机生成一个匿名业务用户 ID，同组轮次复用它。其余输入转换逻辑与第二组一致；随后出现跨进程缓存命中。这支持用户隔离字段是此次零命中的主要原因。实验没有改写 Claude 正式入口的 metadata、认证或身份标识。

因此：

- 新 CLI 进程可以复用上游缓存；进程寿命不等于缓存寿命。
- 本次不能证明 OCP 的缓存断点提高了 DeepSeek 命中率，因为 DeepSeek 忽略该字段。
- OCP 分块机制已通过实际 CLI 输入块数验证（1、3、5、7），但对 Claude 模型的缓存收益尚未测试。
- 没有直接模型基线，不能承诺相对原生模型总成本低于 1.5 倍；目前只验证了改版没有显著增加同任务总输入。

## 审计质量

三次受控测试均完成三次本地读取并给出报告。但 OMP 的 read 对 server.mjs 返回结构摘要，模型仍针对被省略的实现推断漏洞；有时将明确的单并发限制列为问题，还重复声称 no-session-persistence 会关闭上游缓存。这些结论不可靠。

模型针对旧版指出的“非流式工具响应丢失前置文本”，可由旧代码 content:null 确认；新版已累计文本并与全部工具调用一起返回，测试覆盖。未依据模型的误报修改鉴权、tool_choice 或扩大工具权限。下一次正式审计应明确获取完整代码，并逐项复现发现；此次不能作为完整安全审计通过证明。

在上述三组之前，默认思考模式曾用 11 轮网关请求、16 次成功上游请求，消耗未缓存输入 160,556、缓存读取 87,424、输出 78,484，最终反复撞到 8192 输出上限而失败。该组与后三组条件不同，未放入效果对比；保留它是为了说明输出上限与重试也可能成为主要成本。
